## 1. Capped completion is not a uniform subtree sample

prefix.py first creates a breadth-first frontier, shuffles it with a fixed seed0 permutation, and dispatches `_dfs` through `Pool.imap_unordered(..., chunksize=1)`. It consumes results as they finish. In mass mode, it performs grouped numerical integration before incrementing `done`. Only afterward does it test elapsed wall time and terminate the pool on a deadline. Thus membership among completed/consumed subtrees can depend on subtree geometry runtime, mass workload and queue timing. The fixed seed fixes an order; it does not establish equal inclusion probabilities for the retained set.

The source and README label `cells * subtrees / subtrees_done` an unbiased estimate. That label is not justified by this design. A concrete design counterexample:12 tasks,11 parallel workers,11 tasks with duration1/count1 and one task with duration100/count100, deadline0.5 checked after each return. Any initial random ordering starts at least10 short tasks. The first return is short and triggers termination; the recorded count is1 and the extrapolated total is12, while the actual total is111. Every permutation gives the wrong expectation. This refutes the general unbiasedness argument without asserting these durations/counts for the actual run or a known direction/magnitude of its bias. Mass-processing time adds another possible selection mechanism.

The saved k6 record explicitly has complete=false,3811 frontier subtrees and245 consumed results. Its 1,473,541 cells and1,459,727 distinct stored histories describe that partial computation. The scalar `cells_est` is an extrapolation, not a complete enumeration or certified confidence interval. Random dispatch alone does not justify using it as a population estimate. A fixed-size, preselected subtree sample fully completed regardless of runtime would be a different design; it was not this code path.

No completed-subtree indices, individual completion durations/counts or inclusion probabilities appear in the scalar summary. The retained regionmass archive has aggregated patterns/masses but is not decoded here. It cannot be assumed to recover the dispatch/completion registry. Reanalysis cannot invent missing selection information.
