# Pinned scalar body, not full native cost

GCC14.2 library3cd9dd0f and disassembly27035e3a use ordinary scalar SSE instructions, no FMA or packed floating arithmetic. Scheduling reorders independent products but preserves each dependency and tree sum. guard3 body0x1232..0x130b executes19MULSD,4SUBSD,6ADDSD:29 scalar arithmetic. Nonzero allowance executes one more SUBSD/ADDSD and two external nextafter calls. Zero allowance checks point==0 and skips those two arithmetic/calls.

Finite classification loop executes nine128bit ANDPD masks and nine UCOMISD comparisons, even on nonfinite rejection. For finite inputs a second loop executes nine masks, nine zero comparisons, one low-bound comparison per nonzero and one high-bound comparison whenever abs(x)>=2^-100. There is one allowance comparison plus a point comparison on zero allowance. Thus a dense eligible nonzero-allowance case has31 scalar arithmetic,37 scalar FP comparisons and18 packed bitmask instructions, plus two nextafter calls and one fegetround call. These categories are deliberately not collapsed into a purported complete cost. The bitmasks touch128bits but are not two floating arithmetic operations.

The initial runtime guard readsMXCSR and callsfegetround; its integer masks/branches, both loops' integer bookkeeping, loads/stores, function linkage, library bodies and Python/call marshalling remain outside this body count. In particular a hypothetical86-unit sum of arithmetic+comparison+bitmask categories is not a measured full runtime and cannot be compared as a speedup with the earlier104-unit determinant upper subset. Exact fallback is external and separately recorded.

instruction_ledger.py pins expected assembly sites and contracts source-deduced paths over the89 saved inputs without executing the kernel. It is not a dynamic instruction trace. Four environment rejection probes are retained in results.json but excluded from the normal-row count. Compiler, code layout and runtime assumptions are fixed; no portability claim.
