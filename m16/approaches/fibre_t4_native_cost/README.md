# T180: native numerical cost of the T4 fibre recipe

## Question
Does the first completed noisy H8T4 fibre case remain plausible against
sampling once its dense numerical implementation is counted?

## Method
TASKS-only claim53b3dc7e precedes implementation. Root prioritizes this bounded
cost discriminator over seven further noisy copies. Pin T100's exact original
source, local zero guard, model and existing first face component. Inventory
numerical expressions and native calls before adapting reviewed T146/T153
counting helpers. Keep original values, legacy counters and shared files
unchanged. Separate numerical categories, explicit integer control, opaque
kernels, cold setup, memory and omitted runtime work.

Frozen tests: four existing analytic models and exact-zero, nonzero and thin
near-boundary clip controls. Independent source/count review must pass before
only the same original noisy family0/side0 is traced. One thread, 2GB,
110CPU maximum per primary process; preserve unsupported calls, mismatches
and timeouts. No new model, noise, reference draws or estimator tuning.

## Status
Source inventory in progress. T100's first noisy row is complete660786a5 and
awaits independent final aggregate review; no full native cost exists yet.

## Results
Read-only source finding: rows_at executes dense Wh@Ag and Wo@Ag but legacy
charges use active gate counts and elapsed input columns. It also executes
Ag=A*g[:,None]. Thus zeros in arrays are priced as free by parts of the old
counter, although dense NumPy kernels execute them. This is a concrete
counting difference, not a full-model ratio or failure verdict.

## Compute accounting
Inventory only so far. Explicit numerical operations use the same declared
scalar elementary-function units as T146, with integer/control separated.
Cold-only SVD/inverse/rule generation remains explicit and opaque until
justified; no recursive hardware/libm pricing or cost from wall time.

## Claims
[inferred] The native/legacy difference could consume the conditional95%
first-noisy matched-sampling cost budget4.244B, or still leave useful headroom.
[measured] T100's legacy total is1.1666B including local guard; this is not
actual native cost. A single component ratio will not be scaled into a

## Alternatives not ruled out
Dense recurrence undercount may dominate, tested by analytic shape controls.
Alternatively clipping/comparison/reduction work may dominate, tested by a
full per-site ledger on the same first component. If tracing exceeds budget,
a separately reviewed structural counter can be considered after preserving
the failure; no blind rerun or output-based parameter selection.

## Failure modes
Missing native calls, changed short-circuit/receiver evaluation, double
counting nested helpers or setup, omitting masks/reductions, assuming zeros
make dense BLAS sparse, transferring a local ratio to other components, and
promoting a declared numerical subset to complete runtime cost.
