# T121: common-unit as-implemented frozen F2L3 cost audit

## Question
Does the exact slow R4-fixed F2L3 implementation used by T101/T114 have the claimed sampling-equivalent cost when both sides use one arithmetic convention? Claim1e0b205 was pushed before implementation. This review is separate from T97's historical missing-elementwise audit and from the fast path.

## Method
Pin `review/understand_ladder/fibre_strict.py`, its `fiber3.py` dependency and both T101/T114 loaders at shared revision1e0b205. Apply exactly the existing R4 cache-retention line and LOOK=3 in an isolated local module. Preserve historical n/x and all estimates. No shared or author files change.

First bounded discriminator: instrument every executed matrix product in the pinned slow source without altering its operands, ordering or implementation. Independently charge full dense dimensions, record the historical structural-sparsity charge and convert dense products into separate scalar multiply/add counts (length-k dot uses k multiplies and k-1 additions). Also record the source's actual gate-mask multiplications A*g, which execute on all entries. This gives an exact ledger for named kernels, not automatically a complete scalar count for the whole estimator. Separately derive and execute the sampling forward pass with input generation and labels free, first known-zero hidden update skipped, all remaining dense arithmetic, ReLU comparisons, first-index argmax and correctness comparison counted. H4T3 should cost112 scalar operations; the historical72 convention is preserved for comparison.

Freeze controls before runs: zero weights/readouts, an all-positive rational model, and public H4T3 k30 seed0,seed1,seed4 plus k24 seed4; each trained model has its clean state and one fixed absolute-.05 copy generated by PCG64 seed124 (no favorable selection). Verify exact bitwise estimator/traces/historical-count parity between pinned baseline and instrumented execution; reproduce the constant-model1/3 control. Report all setup, caches, source hashes, and remaining uninstrumented categories. No broad noisy panel or new rung claim. After that, decide whether a finite complete scalar recount or an actually executed sparse rescue is justified. No benefit is credited to zeros the dense NumPy operation still multiplies.

Competing explanations: the hybrid units and unimplemented sparsity materially change budget equivalence; or corrections on estimator and sampler cancel enough to preserve comparisons. Independent primitive counts and unchanged-output controls separate these. Another possibility is a numerical/import/cache change introduced by instrumentation; pinned source and output parity must falsify it before cost conclusions.

## Claims

## Alternatives not ruled out
A genuinely sparse implementation, fused-operation versus scalar conventions, further missed elementwise or special-function work, and the separately unreviewed fast path. A bounded kernel inventory cannot certify the entire estimator.

## Failure modes
Changing numerical order while counting; changing cache lifetime; charging a sparse algorithm that was not run; mixing fused and scalar operation units; forgetting model-dependent setup; first-index ties or silent caps; assigning hardware timing to abstract operation counts; selecting models after seeing cost changes.

## Native expression inventory (second bounded phase)
The frozen baseline outputs, n/x, segments and traces again match bitwise in all ten cases. Every matrix multiply/add total also matches the first, independently implemented named-kernel ledger. The inventory no longer carries the old hybrid scalar remainder: arithmetic.py wraps native operators in the pinned functions and imported _Sint without changing operands/order. Primitive controls establish short-circuit comparisons, in-place alias preservation and sorting comparison counts. Zero rows_at is350 operations including the three Boolean reduction operations omitted from the first347 subtotal; nonzero _Sint is20 operations, versus2 on its zero-radius early return. The historical17-per-call charge is retained unchanged, not silently rewritten.

The common comparator uses **all explicitly executed numeric expressions**, including explicit integer index/control expressions, plus the declared reduction/special/sort costs. The exact same AST wrapper applied to an ordinary scalar sampling forward pass produces111 floating operations/comparisons plus1 integer correctness comparison, hence112, on every frozen case. Integer class decisions cannot be discarded from the estimator while charging sampler correctness. Floating-only ratios in the raw JSON are diagnostic subtotals and are not the common-unit comparison.

Under this explicit-expression convention, all eight trained cases have estimator/sampler budget ratios0.805806–0.858590 times their historical ratios; zero and rational-positive fixtures instead have factors1.977350 and1.265606. These ratios do not establish accuracy/MSE success or a whole-implementation cost. They show why a counter increase cannot by itself refute the historical comparison: the sampler unit correction matters. No sparse rescue or fast path was executed.

This convention is deliberately code-form-dependent: explicit t*H index arithmetic is counted, whereas implicit range iteration/increments and interpreter branch machinery are free on both sides. Reductions charge n−1 comparisons/additions/Boolean combines; this is an abstract algebraic convention, not a SIMD instruction measurement. Special functions count one call. Memory allocation, copies, indexing/filtering, np.where/flatnonzero selection, shape/length queries, casts, dictionary/cache lookup, Python short-circuit control machinery, file I/O and instrumentation overhead are excluded. Therefore complete_implementation_cost remains false. All model-dependent State/row construction, repeated cache misses, in-call boundary setup, native dense products, gates, scalar expressions and integrals are included in the declared inventory; module-level model-independent FAMS construction is exempt. Changing the source expression form could change this cost without changing the mathematical method.
