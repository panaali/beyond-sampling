# Conditional retry theorem and separate cleanup qualification

## Q3: at most four Q5 attempts under a zero-shift sign invariant

Assume the pinned code, a legal active block of length at least3, PP0/1, and ordinary nontrapping IEEE round-to-nearest arithmetic. On each retry the input-parity active q entries are nonnegative with positive zero when zero, and active e entries are nonnegative with either sign of zero; negative split markers lie outside the active block. A finite, valid, nonnegative scaled bidiagonal start is consistent with this invariant, but establishing it for every intermediate installed invocation is a separate dependency. The following proof does not assume that all nonzero-shift trials succeed or remain finite.

1. **TTYPE starts at most−1.** Q4's immediate negative-DMIN branch sets−1 (188–190). All other case and early-return paths set one of−2 through−12 before returning; the ordering uses N0<=N0IN from Q3 deflation. Even the guarded early returns in cases4/5/7/10 set their negative type first. Thus stale positive incoming TTYPE does not survive a legal Q4 call.

2. **Three negative failures force zero.** Q3 checks `TTYPE<−22` before adjusting the shift. If false, a negative-DMIN failure subtracts11 (late) or12 (early). From at most−1, after two such failures TTYPE<=−23. Therefore the third negative failure forces TAU=0 and its next attempt is the fourth at latest. The comment “failed twice” is not itself the proof; the branch is checked before the decrement. At most three nonzero-shift attempts precede a forced-zero fourth.

3. **A zero-shift Q5 attempt cannot retry through negative DMIN under the invariant.** Failed trials write only opposite-parity outputs and endpoint metadata, not the active input q/e or PP. With TAU=0, Q5 initializes D=q−0, then uses sums, nonnegative ratios/products and subtraction of zero. Under round-to-nearest the sum of D=+0 and e=−0 is+0; q/denominator cannot produce negative infinity from a negative-zero denominator. The threshold branch only replaces D by+0. All computed D values are nonnegative, positive infinity or NaN; none is a negative finite value or negative infinity. MIN must return one of its operands or NaN (no fast-math assumption manufacturing an unrelated value). DMIN starts nonnegative and keeps this property. The initially negative sentinel DMIN1=−q is overwritten before return because the active length is at least3 and the IEEE branch executes both unrolled tail steps. For non-IEEE/trapping modes this theorem is not asserted.

   Therefore Q3 either accepts (`DMIN>=0 && DMIN1>=0`), sees NaN at TAU=0 and falls through to Q6, or uses the possible-underflow Q6 branch. Neither path returns to label70. Signed zeros compare>=0. One Q6 call returns directly to the shift update; it has no Q3 retry jump.

4. **NaN does not add an extra fifth attempt.** At any nonzero-shift attempt, NaN-DMIN sets TAU=0 immediately; the next attempt exits by step3. A NaN on attempts1/2/3 thus needs at most2/3/4 attempts. If the first three failures are negative, the fourth is already zero shift and cannot retry. Q5 may independently clamp a tiny shift to zero, only shortening this bound.

This gives at most4 Q5 calls and1 Q6 call per Q3 invocation **conditional on the explicit active-array/IEEE invariant**. Q2's displayed `(N+1)*100N` Q3-call ceiling then gives at most8000 Q5 and2000 Q6 calls for N=4 before considering its failure cleanup. These are loose algorithmic attempt ceilings, not numerical operation totals or installed-runtime measurements. NaN/overflow propagation across accepted prior Q3 calls and validity of active-block markers require a separate whole-caller invariant or saved runtime assertion if a universal envelope is claimed. Do not replace this condition by “inputs finite” without proving the implication.

## Q2: INFO=2 cleanup has a separate non-progress state

The source loop at509–530 sets I1=I0, N1=N0 and enters label145. Its body updates q/e coordinates in the **fixed** block I0..N0. On I1>1 it sets N1=I1−1, decrements I1 only while the previous marker Z(4I1−5)>=0, assigns SIGMA=−Z(4N1−1), and jumps back to145. Neither I0 nor N0 is updated in this cleanup.

Consider the control state I0=I1=2, N0=4, Z(3)=−1, with arbitrary current-block data and SIGMA=1. Label145 changes indices5 and above, so Z(3) stays−1. The `DO WHILE` condition is false on its first check; I1 remains2. N1 becomes1 and SIGMA becomes−Z(3)=1. The next label145 visit has exactly the same loop-controlling values. Hence there is no finite syntactic bound on this cleanup path from the loop body alone. Even if updated current-block values overflow, they do not change I1 or Z(3).

This is an internal control-state witness only. No valid initial matrix has been exhibited that reaches INFO=2 in this state, and this review has not established installed binary equivalence. Therefore it is not evidence that a trained matrix hangs. It does invalidate the inference “Q2 has100N outer iterations, therefore all of its paths are bounded by that count” without an additional reachability or source/binary argument. A runtime census over already successful fixed calls is a possible distinct rescue; it would certify measured calls, not all legal matrices.
